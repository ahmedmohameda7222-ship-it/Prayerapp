# TV Layout V2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement each task using TDD.

**Goal:** Translate the user-approved 25-state standalone HTML TV preview into the live mosque TV app and make After Prayer a four-minute fixed Hisn al-Muslim board.

**Architecture:** Existing Feed, prayer/Friday calculators, schedule and content eligibility remain authoritative. A new post-prayer presentation window is resolved only after higher-priority prayer/Friday states, and the V2 presentation layer shares header, six-cell rail and real QR while rendering a distinct hero by state/content kind.

**Tech Stack:** Next 16, React 19, TypeScript 5.9, CSS, Vitest, GitHub Actions CI.

**Spec:** `docs/superpowers/specs/2026-11-14-tv-layout-v2-design.md`

## Global Constraints

- Match approved standalone preview's 1920×1080 composition and 1366×768 TV-safe readability.
- Never fabricate prayer/iqama times, Friday services, donation URLs, or Azkar texts.
- All Post Prayer content comes from existing published, Admin-selected Feed, sorted by `sortOrder`, 4m absolute after completion. Never rotate those items automatically.
- No Sleep Azkar, audio, production database writes, migration, or debug preview controls.
- Keep true QR codes and existing offline/LKG, diagnostics and fullscreen behavior.

## Review Focus

- Post Prayer state starts only after configured congregational duration, ends at 240s, never interrupts a next prayer or Jumuah state.
- Every Jumuah service (primary and additional) opens its own 240s fixed board after its true existing 30m hold.
- Empty or missing post-prayer selection returns normal content instead of an empty fixed board.
- Long Arabic and German content remains in original Feed text; only responsive visual clipping is permitted and communicated.
- 1366×768 and 1920×1080 strip/QR still visible; time-zone and midnight behavior unchanged.
